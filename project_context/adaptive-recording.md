# 按键录音与 3 秒停顿

2026-10-07 用户反馈固定 5 秒在指令结束前切断，明确改为连续安静 3 秒才结束。仍须按一次 Speak，不加入唤醒词或持续监听。

- 在板端以现有双麦每 100ms 的 RMS 最大值判断有声；阈值为静音背景估计的三倍、至少 120。连续有声至少 200ms 才视为有效开口，减少点击瞬态。
- 开口后连续安静 3 秒才完成；1–2 秒停顿后继续说会清零安静计时。不是语义判断或神经 VAD，电视声、持续噪声、过轻/远场声音仍可能误判。
- 最长 20 秒；前 5 秒没有检测到开口或到最长时仍未得到完整停顿，取消并擦除缓冲区，不送 STT / LLM / CAO。正常 Voice 服务会播放固定重说提示，失败也回 Ready，不自动重试。
- PSRAM 最多分配 1,280,000 字节，结束后按真实帧数导出并清零释放。USB BEGIN 长度须大于零、四字节对齐、不超过上限；offset / ACK / SHA-256 校验不变。旧手动 capture_seconds=1…5 固定导出保持兼容。
- STT 输入同步支持最多 20 秒 / 2MiB stereo WAV，在 Mac 转 mono。TTS 和板端播放的 5 秒分段上限、限幅、音量 80 没有扩大。
- 录音、导出、处理、播放仍禁用重复按键，状态和 Host 租约继续沿用。待机时只显示音量，不持续上传或保存用户录音。

验证：原生 C 在 -Wall -Wextra -Werror 下执行真实 endpoint 状态机测试，覆盖说话超过 5 秒、2 秒停顿继续、完整 3 秒停顿、未开口、连续有声到上限及背景噪声；Python 覆盖可变长度 USB 完整性、越界/未对齐拒绝、取消后不残留串口帧、20 秒 mono 转换及超长拒绝。完整 140 项测试通过；两线程 ESP-IDF 增量构建无新增 warning，固件 1,505,632 字节，2MiB 分区剩余 591,520 字节（28%）。已烧录，Wi-Fi / hello / 三次 pong 复验通过。

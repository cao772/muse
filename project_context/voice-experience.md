# Voice MVP 体验优化：状态联动与常驻模型

2026-10-07，基于 `921aefb`（该基线 Gateway / firmware CI 已全部成功）。本轮只优化设备状态和本地模型复用，DeepSeek、Serena、音量 80、PCM 格式与 offset / ACK / SHA-256 校验保持。

## 设备状态与互斥

Mac 启动先发送 Thinking，再预加载/预热两个模型；预热期间不能录音。成功后显示 Ready。

- Ready：允许按一次 Record 5s。固件立即进入 Listening，并在同一临界区锁住第二次触发。
- Listening：设备采集与导出；Record 禁用。
- Thinking：Mac 转录、LLM 和 TTS；Record 禁用。
- Speaking：Mac 下发/设备播放；Record 禁用。
- 完成或本轮失败后返回 Ready；不排队、不自动重播。

状态同时显示在首页和 Audio Input 页，保留网络状态、触控、音量条及 Back / View status。USB 新增元数据命令 `{"voice_state":"Ready|Thinking|Speaking"}`，不包含用户文字/密钥。Listening 由固件录音请求产生。原有音频帧和录音命令不变，旧 USB 导出/播放工具仍可使用；启用 Voice 服务后由主机状态门控录音。

主机每 2 秒刷新状态，有效期 15 秒。失联后屏幕显示 Host offline 并禁用录音，防止无人接收的导出；服务恢复并发送 Ready 后解锁。重复 Ready 不能在采集/导出/上传/播放中解锁。所有 USB 写入共用锁，状态心跳读取当前状态与发送在同一锁中，防止旧 Ready 覆盖新 Thinking。

## 常驻模型

- Whisper：Gateway Python 环境中的独立进程，缓存加载 large-v3-turbo 并进行静音预热，不将预热转录发送给模型。
- Serena：原有独立 TTS Python 环境中的进程，锁定 Qwen3-TTS 0.6B 8bit revision；加载后合成“你好。”预热，音频丢弃、不播放。
- 每轮通过 stdin/stdout 的私有 JSON 行 RPC 传递 WAV/text；请求编号严格匹配且串行执行。库日志从协议输出分离并丢弃，用户音频不落盘、不上传。
- 请求超时：STT 90 秒、TTS 180 秒；初始化最多 180 秒。超时/退出/格式或请求编号异常会终止对应进程，丢弃旧结果，下一轮重载；不自动重发上一轮。
- 明确的 TTS 时长超限属于业务拒绝，保留健康进程并沿用文字分段；仍不截断音频、不修改限幅/5 秒上限。正常多轮不启动完整模型进程。
- 服务退出时终止自己创建的两个模型进程。没有网络 TTS、唤醒词、持续音频监听、全双工或 MCP。

## 已完成验证

- 111 项测试通过，包含原有 105 项；新增实际小型子进程 RPC 的 10 请求进程复用/编号、超时、异常后重载、时长拒绝不重载和取消终止测试。
- 本地固件构建无 warning/error，1504048 字节，比基线增加 832 字节；2MiB app 剩 593104 字节（约 28.28%），不扩分区。已烧录且烧录 hash 校验通过。
- 真机 Wi-Fi → 鉴权 WebSocket → hello → 3 次 ping/pong 通过。
- 真机 Thinking / Speaking 时通过 USB 请求采集均被明确拒绝，没有出现 PCM BEGIN；主机状态过期后请求采集也被拒绝，发送 Ready 可恢复状态。屏幕点击禁用及状态顺序另需人工核验。
- 实际模型预检：相同两个进程运行三轮，后两轮 Whisper 为 0.486/0.421s，短句 Serena 为 0.704/0.665s。加入启动预热后，Serena 两次为 0.678/0.643s，进程未变化。这不是整机对话延迟或不同文字性能保证。

## 耗时口径与基线

基线保留的实机一轮：STT 1.723s、LLM 1.629s、TTS 5.856s、两段播放 6.353s，接收完成到播完 15.562s。基线之后短回复优化有用户确认“比上次快了”，但该轮日志被服务重启覆盖，不伪造精确降幅。

本轮 Done 元数据包含 STT / LLM / TTS / 播放 / 接收完成至播完；首音使用 `MUSE_SPK_PLAYING` 作为软件代理（并非外部麦克风声压检测）。另从 UI Record 请求日志估算录音加导出、按键至首音、按键至播完；不含用户说话前等待 Ready 的时间。固定 5 秒录音仍无法消除。

用户在完成 3 轮后明确将验收范围调整为“3轮就可以了”，按该最新要求收口，不声称 10 轮真机通过。三轮均完成完整采集、转录、真实 DeepSeek 请求、Serena 合成与 hash 验证播放，无失败、无重复 Done，回复各 1 段；用户确认页面状态和忙时按钮“试了没问题”。前后 Whisper / Serena 进程 ID 均为 4887 / 4890，未在三轮之间重启。

## 使用与限制

沿用 `uv run muse-talk --port /dev/cu.usbmodem101`；看到屏幕 Ready 后按 Audio Input → Record 5s。首次启动/故障重载期间会显示 Thinking。可使用 Ctrl-C 结束；停止后 15 秒进入 Host offline。主机恢复后无需重新刷固件；板子重启仍需下发 RAM 配置。

Whisper + TTS 进程常驻增加内存占用；本机为 M5 / 16GB，未证明其他机器资源与耗时。两模型预热时间不计入每轮。设备状态是一条物理 USB 开发链路的主机元数据，没有新增网络音频入口。网络断连/Host offline 与语音 Ready 是不同状态，页面仍保留 Wi-Fi/Gateway 信息。
